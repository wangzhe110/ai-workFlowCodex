# 云雾异步图生视频接入说明

本项目的“视频片段”步骤已接入通用异步视频适配器：先提交图生视频任务，保存
供应商任务号，再轮询直至获得 MP4 地址。它不是把某一家中转站的协议写死在业务
代码里；更换模型或中转站时新增一版步骤模型配置即可，已经开始的任务继续使用
自己的配置快照。

> 提醒：云雾不同视频模型的提交字段、参数和可用路径可能不同。下面的路径和
> 字段是配置模板，不是对所有模型的保证。启用前必须以云雾账户中该模型当前的
> API 文档为准，先在测试项目跑一个镜头组。

## 1. 前置条件

1. 服务端未提交的 `.env` 已有 `YUNWU_API_KEY=真实密钥`，并已重启后端。
2. “分镜图片”步骤已经使用真实图片模型生成成功，且图片地址是供应商可从公网
   读取的 `https://` 地址。
3. 已人工确认分镜。模拟图片产生的 `data:` 地址只用于本地联调，真实视频任务
   会被系统主动拒绝，避免发出无效付费请求。

平台会在“创建视频任务”时检查每组所需的首帧（配置了结束帧时也检查末帧）；不
满足 HTTPS 条件会直接返回可读错误，**不会**提交给视频中转站或产生视频模型费用。

## 2. 在配置中心新建视频模型版本

打开“模型配置中心”，选择“视频片段”。页面会预填通用异步图生视频适配器。最小
配置模板如下：

| 字段 | 模板值 | 说明 |
| --- | --- | --- |
| 供应商标识 | `configurable_async_video` | 已实现并可启用的适配器 |
| 模型标识 | 云雾后台实际视频模型名 | 只用作审计；只有 API 需要模型字段时才填写“模型字段” |
| API 地址 | `https://yunwu.ai` | 视频 API 不应沿用文本/图片的 `/v1` 地址，除非该模型文档明确要求 |
| 密钥环境变量名 | `YUNWU_API_KEY` | 不填写真实 Key |
| 提交路径 | `/luma/generations` | 模板；按所选模型文档核对 |
| 查询路径模板 | `/luma/generations/{task_id}` | `{task_id}` 会替换成提交后返回的任务号 |
| 提示词字段 | `user_prompt` | 若文档要求 `prompt`，改为 `prompt` |
| 首帧请求格式 | `顶层图片地址` | 常见形式是 `image_url`；若文档要求 `keyframes.frame0`，改选关键帧格式 |

“固定请求参数”只填写该模型文档明确支持且不会随镜头改变的参数。例如
`{"duration":"5s","aspect_ratio":"9:16"}`。字段不确定时保持 `{}`，不要凭猜测
开启付费模型。

默认响应映射使用 `id`、`state` 和 `video.url`（兼容 `artifact.video.url`）。如果
实际响应结构不同，在“响应映射”中按该模型文档修改，例如任务号在
`data.task_id` 时填入 `"task_id_path":"data.task_id"`。

## 3. 状态、失败与重做

- 提交后任务保持 `PENDING`，平台按配置的间隔轮询；通常会把供应商的
  `pending`、`processing` 等状态统一为等待中，把 `completed` 统一为成功。
- 每个镜头组有独立任务号、图片版本、提示词和视频版本。一组失败不会抹掉其他
  已成功的组。
- 点击“重做此组”会创建一个新的创作版本；工作流“重试”只重投同一次失败运行，
  不会伪造新的版本号。
- 本地演示使用进程内后台任务。生产必须将同一执行函数交由 Redis/Celery/RQ 等
  独立 Worker 消费，并补充任务恢复、死信队列与监控，避免 Web 进程重启中断轮询。

## 4. 生产上线前验收

对每个候选视频模型至少验证：

- 单任务提交、轮询、失败响应和最终 MP4 URL 都能被正确解析；
- HTTPS 首帧图片在任务完成前不会失效；必要时先保存到自己的 S3/MinIO；
- 时长、画幅、单组镜头数、耗时、成功率和单条成本达到预期；
- 输出角色一致性、画面质量、内容合规和版权风险通过人工审核；
- 使用测试密钥或限额做小流量验证，确认后再在配置中心启用。
