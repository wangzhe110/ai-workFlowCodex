# 云雾语音转写接入说明

“参考视频分析”现在由两个独立步骤构成：

1. `transcribe_reference_audio`：提取参考视频开头的一小段音轨，并在 Worker 内存中调用语音转写模型；
2. `analyze_reference_mechanisms`：将抽样画面帧与临时转写文本综合为开头钩子、节奏、情绪和冲突等**抽象原创机制**。

这样可以单独替换 ASR（语音转写）模型或视觉模型，也可分别比较成本、速度和结果质量。

## 内容与数据边界

- 仅处理用户确认有权分析的参考视频；V1 只提取开头有限时长的音轨，默认 180 秒。
- 音频临时文件在 Worker 任务结束前删除；转写原文只在该次任务内存中交给综合分析。
- 数据库和前端仅能看到是否检测到语音、音频预算、执行状态和最终抽象机制，**不会保存或展示原台词**。
- 综合分析提示和输出契约禁止复述或建议复用原视频台词、人物、画面、音乐、字幕或具体剧情。

## 配置中心填写方式

在“模型配置中心”选择“参考视频语音转写”，填写并启用一版候选配置：

| 字段 | 建议值 |
| --- | --- |
| 供应商标识 | `openai_compatible_transcription` |
| 模型标识 | 云雾账户中实际可用的语音转写模型名 |
| API 地址 | `https://yunwu.ai/v1` |
| 密钥环境变量名 | `YUNWU_API_KEY` |
| 分析开头音频上限 | 180 秒起步，允许 5–600 秒 |
| 音轨提取超时 | 120 秒起步，允许 5–300 秒 |
| 音频请求体上限 | 8,388,608（8 MiB）起步，允许 64 KiB–50 MiB |

适配器使用标准 `POST /v1/audio/transcriptions` multipart 请求，固定发送：

- `file`：Worker 临时提取的单声道 16 kHz MP3；
- `model`：当前运行快照中的模型标识；
- `response_format=json`：保证服务能安全读取 `text` 字段；
- `transcription_request_options`：可填写供应商文档明确支持的非敏感参数，例如 `{"language":"zh"}`。

扩展参数不得覆盖 `file`、`model` 或 `response_format`。真实 Key 只在后端/Worker 的未提交 `.env` 或密钥管理器里设置，不能填入配置中心。

## 本地与生产行为

- 默认的“本地模拟语音转写（不读取音轨）”不会安装 FFmpeg、不会访问第三方、也不会读取原视频声音，便于完整流程演示。
- 启用真实转写前，API 和 Worker 所在环境都应安装 `ffmpeg`；使用 Redis/RQ 时，执行该任务的 Worker 镜像也必须安装它，并能访问 `LOCAL_STORAGE_PATH` 的同一素材目录。
- 本地存储可直接挂载 `LOCAL_STORAGE_PATH`；生产可设置 `SOURCE_VIDEO_STORAGE_MODE=s3`，由 Worker 从 S3/MinIO 下载临时源视频后执行转写/视觉分析，任务结束立即清理。
- 每次点击分析都会冻结转写模型和视觉模型的版本、参数和环境变量名称；之后切换配置不影响历史运行。

## 验收与排错

1. 先使用一个确定含普通话语音、且已获授权的短视频，在配置中心启用转写模型和视觉模型。
2. 工作台会依次显示“提取语音开头机制”和“提取画面与综合原创机制”。语音步骤的结果中应看到 `transcript_persisted: false`。
3. 若出现“需要安装系统依赖：ffmpeg”，请在**实际执行 Worker 的环境**安装 FFmpeg。
4. 若出现“音轨提取失败”，检查视频是否有可解码音轨、Worker 是否有读素材权限，以及音频时长/超时预算是否合适。
5. 若出现 HTTP 4xx/5xx，按云雾当前模型文档检查 ASR 模型名、账户权限、音频格式能力和 API 地址；不要把真实 Key 写入错误信息或数据库。

若只想先验证画面机制，可保留默认的模拟转写配置，仅启用视觉分析模型；此时最终分析会明确标记未使用音频机制。
