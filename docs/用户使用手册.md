# AI 短剧生产工作流平台：用户使用手册

这份手册面向不写代码的制作人员。你不需要理解模型、数据库或接口，只需要按页面顺序
完成“项目 → 分析 → 创作 → 分镜 → 图片 → 视频 → 成片”。

## 先了解两条原则

1. 平台分析参考视频时，只提炼开头信息释放、冲突、节奏、情绪和镜头功能等**抽象规律**。
   不要把别人的人物、台词、画面、音乐、屏幕文字、完整情节或镜头素材直接搬到新作品中。
2. 只上传你有权使用、授权分析或自行制作的参考视频。平台不能替你取得版权或肖像授权。

## 一、首次打开平台

首次部署由项目负责人完成。使用 Docker 部署时，打开浏览器访问：

`http://127.0.0.1:5173`

如果无法打开，先让负责人访问 `http://127.0.0.1:8000/ready`：页面显示 `ok` 说明后台已
准备好；否则不要反复点击生成，先检查部署状态。

## 二、新建一个短剧项目

1. 在首页点击“新建项目”。
2. 填写项目名称，例如“都市悬疑短剧第一季”。
3. 在创作方向中写清楚你想做的原创方向，例如“都市悬疑、女主视角、节奏快、每集结尾留反转”。
4. 进入项目工作台，上传一条有权分析的参考视频。支持常见 MP4、MOV、MKV、WebM 格式。

不要上传太长或太大的视频做第一轮测试。先用一条典型参考视频确认工作流和模型都正常，
再批量生产。

## 三、分析参考视频，但不复制它

在项目工作台点击“开始分析”。系统会依次：

1. 提取开头有限音轨的节奏与信息功能（不会保存原始转写内容）。
2. 抽取少量画面帧，分析开头钩子、冲突类型、节奏和镜头功能。
3. 返回“开头机制、爆点元素、节奏建议”等抽象结果。

分析完成后，先人工检查结果。好的结果应该是“前 3 秒给出异常事件”“每 8–15 秒推进新信息”
这类规律；如果结果出现具体角色、台词、画面或剧情复述，不要把它用于后续创作，联系项目
负责人调整模型提示词或审核规则。

## 四、建立可复用的创作资产库

打开“创作资产库”，可手动维护两类内容：

- **爆点元素**：如身份反差、目标与阻碍、倒计时、误会升级。
- **开头模式**：如异常事件、限时任务、信息反转、角色立即选择。

写法要抽象、可迁移。例如写“婚礼前出现改变选择的异常消息”，不要写某个参考作品的角色名、
台词或具体事件。以后生成选题时，平台会把这里的已启用内容作为原创创作提示。

## 五、从选题到故事包

按页面顶部的生产顺序操作：

1. **原创选题**：点击生成，查看多个候选的标题、开头钩子和概要。人工确认一个选题。
2. **故事创作**：基于已确认选题生成故事大纲、角色卡和场景卡。检查人物目标、冲突和结尾悬念后，人工确认一个故事包。
3. **分镜细纲**：填写需要的镜头数量，生成并检查镜头、时长、画面、台词/旁白、图片提示词和视频提示词。确认后才能开始生成图片。

任何一层不满意，都建议回到对应层新建一版，而不是直接把后面的视频结果当成最终成片。每一版
都会保留历史，方便比较与回退。

## 六、生成图片、视频和完整成片

1. 在“分镜图片”页生成镜头图片。某一镜不满意时，只重做这一镜；新结果会成为新版本，不会覆盖旧图。
2. 在“视频片段”页选择每组镜头数（默认建议 4 镜一组）后生成视频。视频按组独立生成，某一组失败或效果不好时，只重做该组。
3. 片段检查完成后，点击“合成完整成片”。平台会冻结这次实际选用的片段版本；以后重做某一组，再次导出会产生新的成片版本，不会破坏旧成片。

本地模拟模式会显示流程成功，但不会生成真实可下载 MP4。只有配置并启用真实图片、视频和
FFmpeg 成片模型后，才会得到真实媒体文件。

## 七、模型配置：先测试，再启用

“模型配置中心”由项目负责人或模型测试人员使用。每一个工作流步骤都可选不同的模型版本。
真实 API Key 永远不填在网页里，只能由负责人写入服务器部署密钥。

推荐操作顺序：

1. 新增候选配置时不要立刻启用。
2. 点击“基础预检（不生成内容）”，处理适配器、参数、密钥或连接问题。
3. 创建一个小测试项目。文本/图片/分析类模型用少量样本验证；异步图生视频先只生成 1 组镜头。
4. 在该模型版本中点击“记录 / 查看模型实测”，填写样本数、成功数、总成本、平均耗时和质量评分。
5. 在页面顶部“模型实测对比”中，只比较相同测试场景的数据，再决定是否启用。

不要因为单次便宜就直接切换生产模型。应优先看成功率、单个成功样本成本、质量和耗时的综合结果。

## 八、任务失败或一直执行时怎么办

1. 先看工作流时间线中哪一步失败，并阅读中文错误提示。
2. 常见原因：模型密钥未配置、模型名不可用、中转站余额/权限不足、图片 URL 不可公网访问、Worker 或 Redis 未启动。
3. 修正后点击“重试该工作流”。重试会保留次数，不会覆盖已经成功的历史版本。
4. 如果任务长时间保持“执行中”，系统超过安全时间会自动标记为失败并提示检查 Worker、Redis 和模型平台。它不会盲目自动重放模型请求，以避免中转站超时后重复扣费。

若同一错误连续出现，不要连续点击重试。记录错误、模型配置版本和发生时间，交给项目负责人排查。

## 九、日常备份

日常使用者不需要执行恢复操作，但应知道：项目记录和媒体文件都需要备份。项目负责人应至少
每天备份 PostgreSQL，并启用对象存储版本化/复制来保护源视频、图片和成片。恢复会覆盖数据库，
只能由负责人按照 `运维备份恢复说明.md` 执行。

## 十、制作前检查清单

- 参考视频已获授权，且只用于提炼抽象创作规律。
- 创作方向、选题、故事和分镜均已人工确认。
- 使用真实模型前已完成基础预检和小样本验收。
- 图生视频使用的首帧图片为稳定、可公网访问的 HTTPS 地址。
- 成片导出前已检查每一组视频片段。
- 重要项目开始批量生成前已完成数据库与媒体备份。
