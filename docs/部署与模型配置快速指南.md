# 部署与模型配置快速指南

这是一份给项目负责人使用的操作说明。目标是让你不需要阅读代码，也能完成：

1. 把平台在自己的电脑上完整启动；
2. 验证前端、后端、数据库和任务 Worker 都正常；
3. 安全地写入中转站 API Key；
4. 为每个工作步骤选模型、先测试、再启用；
5. 知道哪些功能目前是模拟，哪些功能配置后可以真实生产。

如果你第一次接触模型配置，请先只阅读 `模型配置小白操作卡.md`。本指南保留了 Docker、
对象存储和视频 API 等部署细节，适合在你完成第一次小样本测试后，或由技术人员协助时使用。

> 重要：当前 V1 尚未实现用户登录、权限和公网访问控制。因此本指南的 Docker 部署仅适合**你自己的电脑或受控内网验收**，不要将端口直接暴露到公网。以后要面向外部人员正式使用，必须先补齐登录、权限、HTTPS 域名、访问限制、日志监控和备份策略。

## 先分清两种启动方式

| 用途 | 推荐方式 | 适合谁 | 结果 |
| --- | --- | --- | --- |
| 看页面、熟悉操作、开发调试 | 本地开发启动 | 开发人员 | 前后端各开一个终端；默认 SQLite 和模拟模型 |
| 自己电脑完整验收、真实调用模型 | Docker Desktop 一键启动 | 项目负责人 | 前端、API、数据库、Redis、Worker、素材存储一起启动 |

如果你的目标是“开始实际做短剧”，请直接使用下面的 **Docker 完整启动**。本地开发启动只用于排查页面或接口问题。

## 一、首次准备（只做一次）

### 1. 安装 Docker Desktop

在 Mac 上安装并打开 Docker Desktop，等待状态显示正在运行。然后打开“终端”，执行：

```bash
docker --version
docker compose version
```

两条命令都能显示版本号，才说明 Docker 可以使用。若提示“command not found”，说明 Docker Desktop 未安装或尚未启动。

### 2. 进入项目目录

```bash
cd /Users/macpro/Documents/Codex/2026-08-01/plugin-computer-use-openai-bundled-play/ai-drama-workflow
```

后文所有命令都默认在这个目录执行。可以先执行 `pwd`；屏幕应显示上面的完整路径。

### 3. 创建两份本机私密配置文件

执行：

```bash
cp infra/compose.env.example infra/compose.env
cp infra/backend.env.example infra/backend.env
```

这两个文件只属于你的部署环境，不应提交到代码仓库或发给他人：

- `infra/compose.env`：数据库和本机 MinIO 的密码；
- `infra/backend.env`：模型中转站的 API Key、未来的对象存储密钥。

打开 `infra/compose.env`，把以下两项改成你自己设置的长密码，不要保留示例内容：

```dotenv
POSTGRES_PASSWORD=换成你自己设置的长密码
MINIO_ROOT_PASSWORD=换成你自己设置的长密码
```

此阶段还没有模型 Key，也可以先启动系统；页面会使用安全的模拟模型。

## 二、完整启动项目（推荐）

### 1. 启动全部服务

在项目根目录执行：

```bash
docker compose --env-file infra/compose.env up --build
```

第一次启动会下载镜像、安装依赖和构建前端，通常比以后启动慢。终端持续显示日志是正常的；**不要关闭这个终端**。

启动完成后浏览器打开：

- 平台页面：`http://127.0.0.1:5173`
- 后端接口文档：`http://127.0.0.1:8000/docs`
- 后端就绪检查：`http://127.0.0.1:8000/ready`

其中 `/ready` 显示 `ok`，表示 API、PostgreSQL 和 Redis 都已就绪。只有 `/health` 成功不代表任务 Worker 已能生产内容。

### 2. 检查所有服务状态

另开一个终端，仍进入项目目录，执行：

```bash
docker compose --env-file infra/compose.env ps
```

以下服务正常运行，才算完整启动：

| 服务 | 作用 | 必须状态 |
| --- | --- | --- |
| `postgres` | 保存项目、版本、工作流和模型配置 | running / healthy |
| `redis` | 任务队列 | running / healthy |
| `migrate` | 升级数据库结构 | exited (0) |
| `api` | 后端接口 | running / healthy |
| `worker` | 真正执行模型、FFmpeg、轮询视频任务 | running |
| `web` | Vue 前端页面 | running / healthy |

如果某一个服务异常，查看对应日志，例如：

```bash
docker compose --env-file infra/compose.env logs worker
docker compose --env-file infra/compose.env logs api
```

### 3. 日常停止与再次启动

停止服务：在启动日志的终端按 `Ctrl + C`，再执行：

```bash
docker compose --env-file infra/compose.env down
```

这不会删除项目数据、数据库或素材。

以后再次启动，不改代码时执行：

```bash
docker compose --env-file infra/compose.env up -d
```

如改过代码或 Docker 配置，再使用：

```bash
docker compose --env-file infra/compose.env up --build
```

## 四、先认识八个生产步骤

每个步骤可以选择不同模型；一个步骤切换模型不会影响其他步骤，也不会改写历史任务。新任务会自动冻结当时启用的模型版本。

| 平台页面/步骤 | 实际做什么 | 当前可用模型适配器 | 模型需要具备的能力 |
| --- | --- | --- | --- |
| 参考视频语音转写 | 提取参考视频开头有限音频，用于辅助分析 | `openai_compatible_transcription` | 标准 OpenAI 兼容 `/v1/audio/transcriptions`，能返回 JSON 文本 |
| 参考视频分析 | 抽样视频画面，提炼开头钩子、冲突、节奏等抽象机制 | `openai_compatible_vision` | 支持图片输入、JSON 输出的视觉模型 |
| 原创选题 | 基于创作资产和抽象机制产出原创选题 | `openai_compatible` | 支持稳定 JSON 输出的文本模型 |
| 故事创作 | 生成大纲、角色卡、场景卡 | `openai_compatible` | 支持稳定 JSON 输出的文本模型 |
| 分镜细纲 | 把故事拆为镜头、画面和提示词 | `openai_compatible` | 支持稳定 JSON 输出的文本模型 |
| 分镜图片 | 根据镜头提示词生成首帧图片 | `openai_compatible_image` | OpenAI 兼容图片生成，返回图片 URL 或 Base64 |
| 视频片段 | 以首帧和提示词生成按组的视频片段 | `volcengine_ark_video` | 参考流程固定为火山方舟的 `doubao-seedance-2-0-mini-260615`；系统已内置任务提交和查询协议 |
| 完整成片导出 | 将已成功的视频片段按顺序转码合并为 MP4 | `ffmpeg_concat` | 不需要 AI 模型；需要 Worker 内有 FFmpeg 和片段 HTTPS 地址 |

初次安装时，这八步默认都是 `mock_provider`（模拟模型）。模拟模式可以验证页面、版本和任务流程，但：

- 不会真的把音频或画面发到云雾；
- 不会真实生成图片或视频；
- 模拟成片显示 `mock://`，不能下载 MP4。

## 五、配置模型的正确顺序

### 第 1 步：只在服务器密钥文件填写 API Key

用编辑器打开 `infra/backend.env`，分别填入云雾和火山方舟的真实 Key：

```dotenv
YUNWU_API_KEY=你的真实密钥
ARK_API_KEY=你的火山方舟真实密钥
```

保存后重启 API 与 Worker，让它们重新读取密钥：

```bash
docker compose --env-file infra/compose.env up -d --force-recreate api worker
```

**绝对不要**把真实 Key 填入网页的“模型配置中心”。网页中的变量名只是引用；系统会拒绝保存疑似密钥字段。

如果你将来改用另一个视频中转站，可以保留以上 Key，同时加一个独立变量，例如：

```dotenv
RELAY_VIDEO_API_KEY=另一个中转站的视频模型密钥
```

再在该视频模型配置中填写密钥环境变量名 `RELAY_VIDEO_API_KEY`。这样无需改动其他步骤。

### 第 2 步：在网页创建“候选配置”

进入平台首页左侧的“模型配置中心”。一次只配置一个步骤，填写时先不要勾选“创建后立即启用”。保存后，该配置是候选版本，不会影响正在使用的生产模型。

下面的表是云雾 OpenAI 兼容接口的安全起点。**模型标识必须以你的云雾账户后台实际可用列表为准，不能照抄不存在的模型名。**

| 要配置的步骤 | 供应商标识 | API 地址 | 密钥环境变量名 | 其他关键参数 |
| --- | --- | --- | --- | --- |
| 原创选题、故事创作、分镜细纲 | `openai_compatible` | `https://yunwu.ai/v1` | `YUNWU_API_KEY` | 超时建议 90–180 秒 |
| 分镜图片 | `openai_compatible_image` | `https://yunwu.ai/v1` | `YUNWU_API_KEY` | 填入该模型支持的图片尺寸，如 `1728x2304` |
| 参考视频分析 | `openai_compatible_vision` | `https://yunwu.ai/v1` | `YUNWU_API_KEY` | 抽帧数量从 6 开始 |
| 参考视频语音转写 | `openai_compatible_transcription` | `https://yunwu.ai/v1` | `YUNWU_API_KEY` | 开头音频上限从 180 秒开始；扩展参数可为 `{"language":"zh"}` |

视频片段固定使用火山方舟的 `doubao-seedance-2-0-mini-260615`，且它**不是云雾渠道**。
网页已经固定使用 `volcengine_ark_video` 适配器，制作人员只选择画幅和时长；提交任务、查询
结果、首帧字段和视频地址的读取均由系统完成。详细操作见 `豆包Seedance视频操作说明.md`。

完整成片不需要中转站 Key。在“完整成片导出”中创建并启用：

| 字段 | 填写值 |
| --- | --- |
| 供应商标识 | `ffmpeg_concat` |
| 模型标识 | `ffmpeg-concat-v1` |
| API 地址、密钥环境变量名 | 留空 |
| 下载/转码上限 | 先保留页面默认值 |

### 第 3 步：基础预检，再做小样本

每一个候选配置都按以下顺序操作：

1. 点击“基础预检（不生成内容）”。
2. 若预检失败，按中文提示修正 API 地址、变量名、模型名或服务启动问题。
3. 预检通过后，新建一个测试项目。
4. 文本、图片、视觉、转写模型只使用少量样本；视频模型只生成 **1 组镜头**。
5. 确认输出质量、耗时、成本和失败处理符合预期。
6. 在该候选配置下记录模型实测数据，再点击“启用此版本”。

视频片段的预检不会真实联网提交任务，以防意外扣费；它会检查 `ARK_API_KEY` 和内置协议。因此即使显示“通过”，也仍必须用 1 组镜头实测。

### 第 4 步：按这个推荐次序逐步接入

不要一次开启八个真实模型。推荐顺序是：

1. 文本模型：原创选题 → 故事创作 → 分镜细纲；
2. 图片模型：先生成 1–2 个镜头，确认尺寸和人物风格；
3. 视觉分析：用一条已授权短视频，检查输出是否只描述抽象机制；
4. 语音转写：确认有声音的视频可以分析，但原台词不会出现在页面；
5. 视频模型：先确保分镜图片是第三方可访问的 HTTPS 地址，然后只生成 1 组；
6. FFmpeg 合成：确认所有视频组成功，并且 URL 在合成期间仍可下载，再导出 MP4。

## 六、真实视频模型前必须处理的图片地址

第三方图生视频模型无法读取你电脑里的 `localhost` 图片，也不能使用模拟图片的 `data:` 地址。真实视频模型开始前必须满足：

1. 分镜图片已经由真实图片模型生成成功；
2. 图片地址是第三方服务能访问的 HTTPS 地址；
3. 图片不会在视频任务完成前过期。

单机验收时可先保持 `GENERATED_IMAGE_DELIVERY_MODE=direct`。多机或正式生产必须使用自己的对象存储/CDN，并改为：

```dotenv
SOURCE_VIDEO_STORAGE_MODE=s3
GENERATED_IMAGE_DELIVERY_MODE=s3
FINAL_VIDEO_DELIVERY_MODE=s3
```

同时在 `infra/backend.env` 填写 S3 端点、Bucket、公开 HTTPS 地址和最小权限凭据。Compose 自带的 MinIO 仅用于本机调试；它的 HTTP 地址不能直接给第三方视频模型使用。

## 七、每天怎么使用平台

1. 确认 `http://127.0.0.1:8000/ready` 返回 `ok`。
2. 打开 `http://127.0.0.1:5173`，新建项目。
3. 上传有授权的参考视频，只分析抽象机制，不复刻具体人物、台词、画面、音乐或剧情。
4. 按顺序完成：分析 → 创作资产库 → 原创选题 → 故事包 → 分镜细纲。
5. 人工确认分镜后，生成图片；再按组生成视频。
6. 检查各视频组后导出完整成片。
7. 某一步失败时先看工作流时间线的中文错误；修正原因后再重试，避免对视频中转站反复提交造成重复扣费。

## 八、最常见的问题

| 现象 | 最先检查什么 |
| --- | --- |
| 浏览器打不开平台 | `docker compose ... ps` 中 `web` 是否运行；确认访问的是 5173 端口 |
| 页面能打开但一直无法生成 | `http://127.0.0.1:8000/ready` 是否为 `ok`；检查 `worker` 是否运行 |
| 提示密钥未配置 | `infra/backend.env` 是否有对应变量；例如模型配置写的是 `YUNWU_API_KEY`，文件中也必须是同名变量；重启 api 和 worker |
| 预检无法连通模型 | 检查 API 地址、模型中转站余额/权限、网络和模型名；不要把 Key 复制到网页或错误截图中 |
| 图片能生成，视频任务不提交 | 首帧是否是稳定可公网访问的 HTTPS URL；检查视频模型的提交路径、字段名与文档是否一致 |
| 视频一直等待或失败 | 查看 `docker compose ... logs worker`；核对查询路径、状态字段、响应映射、最长轮询时间 |
| 成片不能下载 MP4 | 当前是否仍是模拟成片；确认已启用 `ffmpeg_concat`，所有视频 URL 可下载，Worker 正常运行 |

## 九、从“本机验收”到“正式上线”还差什么

本机 Docker 已经可以让你完成整条真实生产链路的验收；但公开上线前还需要一个独立阶段，至少包括：

- 用户登录、角色权限、项目隔离；
- 域名、HTTPS、反向代理和访问限制；
- PostgreSQL、Redis 和对象存储的托管服务或高可用部署；
- S3 私有 Bucket、CDN、对象存储版本化和异地备份；
- 监控、告警、错误日志、模型费用限额和审计；
- 生产密钥管理器，不再依赖服务器文件；
- 压测 Worker 并发、长视频任务、失败重试和成本上限。

在这些能力完成前，请把当前系统视为“内部生产工具”，不要以无登录状态公开给陌生用户。
