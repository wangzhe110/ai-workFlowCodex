# 运维备份恢复说明

本平台的数据分为两类：

- **PostgreSQL**：项目、工作流、模型配置版本、评测记录、素材的元信息和成片版本关系。
- **媒体对象**：用户上传视频、模型图片、视频片段和最终 MP4。生产部署应保存在受控 S3/MinIO，不应只依赖某一台 Worker 的本地磁盘。

两类数据必须一起具备恢复方案；只恢复数据库会得到“有记录但文件不存在”的项目，只恢复
对象存储则无法找回项目、版本和任务关系。

## 推荐频率

- PostgreSQL：每天至少一次全量逻辑备份；重大模型配置切换或批量生产前再手动备份一次。
- 媒体对象：启用 Bucket 版本化和生命周期规则；至少每天检查一次跨 Bucket/跨区域复制或离线归档是否成功。
- 每月：在隔离环境完成一次恢复演练，验证能启动 API、看到项目记录，并随机播放一条已备份成片。

## 本机 Docker Compose 备份

先确认已按 `infra/README.md` 启动服务，然后执行：

```bash
bash infra/scripts/backup_postgres.sh /Users/你的用户名/Backups/ai-drama
```

脚本会输出一个 `.dump` 文件。请把它复制到不与部署机器共失效的安全位置。该文件可能包含
项目名称、工作流错误和模型评测备注，应按业务数据妥善保管。

## 恢复前检查

恢复会覆盖当前 PostgreSQL。执行前必须：

1. 确认要恢复的备份日期、环境和文件大小正确。
2. 确认对应媒体 Bucket/备份也可用。
3. 通知正在使用平台的人暂停创建项目和生成任务。
4. 优先在隔离环境演练。生产恢复应由有权限的运维人员执行。

本机恢复命令如下，必须显式带确认参数：

```bash
bash infra/scripts/restore_postgres.sh /绝对路径/ai-drama-postgres-时间.dump --confirm-restore
```

脚本会先额外备份当前数据库，然后停止 API 和 Worker，执行恢复，最后重新启动 API 和
Worker。恢复后访问 `/ready`；返回 `ok` 后再进入前端检查项目和媒体。

## 生产注意事项

- 不要把数据库端口、Redis、MinIO 控制台暴露到公网。
- 备份文件和对象存储访问密钥都应进入密钥管理和访问审计，不能提交到仓库。
- 恢复数据库后，排队中的旧 RQ 任务可能指向已失效的运行状态。清理或隔离旧队列，再让用户从界面人工重试失败任务。
- 模型 API Key 遗失或泄露时，应先在中转平台轮换密钥，再更新部署 Secret 并重启 API/Worker；备份中不应包含密钥值。

## 每次发布前

项目负责人应在部署机器或相同依赖环境运行：

```bash
bash infra/scripts/verify_release.sh
```

它会在临时数据库上验证 Alembic 迁移、运行后端测试、构建 Vue 生产包，并检查备份恢复
脚本语法。通过后再按“备份数据库 → 升级迁移 → 启动 API/Worker/Web”的顺序部署；脚本
不会替代真实环境的 Docker 启动、模型小样本验收或备份恢复演练。
