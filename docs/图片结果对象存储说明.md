# 图片结果对象存储说明

图生视频通常要求供应商能从公网读取首帧图片，但图片模型返回的 CDN 地址可能会
过期。平台提供两种图片交付模式：

- `direct`：默认开发模式，直接保存图片模型返回的 URL；不增加存储费用，但依赖
  供应商 URL 的可访问性和有效期。
- `s3`：生产建议模式。图片成功生成后，Worker 立刻下载并上传到自有 S3/MinIO
  兼容存储，数据库保存由 `S3_PUBLIC_BASE_URL` 组成的稳定 HTTPS 地址。

完整成片也有独立交付模式：`FINAL_VIDEO_DELIVERY_MODE=local`（默认，单机保存并
经 API 下载）或 `s3`（生产建议，将 FFmpeg 输出流式上传至同一 Bucket/CDN）。

## 生产配置

在未提交的 `.env` 或部署密钥管理器中设置：

```dotenv
GENERATED_IMAGE_DELIVERY_MODE=s3
FINAL_VIDEO_DELIVERY_MODE=s3
S3_ENDPOINT_URL=https://s3.example.com
S3_BUCKET=ai-drama-media
S3_PUBLIC_BASE_URL=https://cdn.example.com/ai-drama-media
AWS_ACCESS_KEY_ID=部署环境密钥
AWS_SECRET_ACCESS_KEY=部署环境密钥
```

`S3_PUBLIC_BASE_URL` 必须是视频中转站可访问的 **HTTPS** 域名或 CDN 地址。它可以
与 S3 API 地址不同；例如 MinIO API 只对内网开放，而 CDN/反向代理负责公开读取。
不要使用带临时签名、很快过期的下载 URL 作为视频首帧。

## 行为与安全约束

- 只会下载图片模型返回的 HTTPS 地址，限制类型为 `image/*`，默认最大 25 MB；
  这些限制可通过 `GENERATED_IMAGE_MAX_BYTES` 和超时配置调整。
- 生成对象键包含项目、分镜、镜头和版本，不会覆盖历史图片。
- S3 凭据只由 SDK 从服务端环境读取，模型配置页面、数据库和前端均不接触凭据。
- 若转存失败，该镜头图片任务会失败并记录可读原因；不会静默回退到易失效的
  第三方 URL。
- 当 `FINAL_VIDEO_DELIVERY_MODE=s3` 时，完整 MP4 会使用项目和成片 ID 组成的新
  对象键流式上传，返回稳定 HTTPS 下载地址；不会在 Worker 内存重复加载 GB 级文件。

## 本地 MinIO 注意事项

`docker-compose.yml` 中的 MinIO 仅用于本地开发，默认 HTTP 地址不能直接作为真实
图生视频的首帧来源。生产需要使用 HTTPS 反向代理/CDN、最小权限访问密钥、私有
Bucket、生命周期规则和备份。配置完成后，为每个候选图片模型和视频模型做一轮小
样本转存与视频生成验收，再启用生产模型版本。
