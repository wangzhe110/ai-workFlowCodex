# LemonFlow V1 部署与模型配置快速指南

本文给负责部署和模型配置的人使用。第一次请先使用本地模拟完成闭环，再以一条 10–20 秒的授权视频做真实小样本；不要直接批量生产。

## 1. 本机近生产启动（推荐）

在项目根目录执行：

```bash
cp infra/compose.env.example infra/compose.env
cp infra/backend.env.example infra/backend.env
docker compose --env-file infra/compose.env up --build
```

服务启动后：

- 前端：`http://127.0.0.1:5173`
- API 健康检查：`http://127.0.0.1:8000/health`
- API 就绪检查：`http://127.0.0.1:8000/ready`
- OpenAPI：`http://127.0.0.1:8000/docs`

`/health` 仅表示 API 进程存活；`/ready` 同时检查数据库和 Redis。Compose 会运行迁移，并启动 PostgreSQL、Redis、MinIO、API 和 RQ Worker。

## 2. 生产启动顺序

1. 备份 PostgreSQL 和媒体对象。
2. 在生产密钥管理器或不提交的环境文件中配置数据库、Redis、对象存储和模型 Key。
3. 先执行迁移：

   ```bash
   cd server
   DATABASE_SCHEMA_MODE=migrate alembic upgrade head
   ```

4. 启动 API，再启动独立 RQ Worker。生产须设置：

   ```dotenv
   TASK_EXECUTION_MODE=rq
   REDIS_URL=redis://你的-redis:6379/0
   ```

5. 使用 `/ready`、Worker 日志和一条本地模拟项目确认服务可用。

不要让 API 或 Worker 在启动时自行建表/改表。

## 3. 模型 Key 放在哪里

模型 Key 只可放在服务器环境变量或未提交的 `infra/backend.env`。例如：

```dotenv
GEMINI_OR_PROXY_KEY=真实密钥
CLAUDE_OR_PROXY_KEY=真实密钥
BANANA_OR_PROXY_KEY=真实密钥
ARK_API_KEY=真实密钥
```

每个模型配置里填写对应的 `secret_env_name`，例如 `ARK_API_KEY`。网页、数据库、导出的追溯信息都只保存变量名和脱敏信息，绝不保存密钥值。修改环境变量后必须重启 **API 和 Worker**。

## 4. 按能力槽位配置模型

打开 `http://127.0.0.1:5173/model-profiles`，为以下槽位创建候选配置：

| 槽位 | V1 目标模型/能力 | 常用 Adapter |
| --- | --- | --- |
| 视频分析 | Gemini 3.1 Pro Preview 或兼容视觉模型 | `openai_compatible_vision` |
| 故事生成 | Claude Sonnet 4.6、Claude Opus 4.6、Gemini 3.1 Pro Preview 并行 | `openai_compatible` |
| 角色、场景、导演分镜 | 可独立替换的文本模型 | `openai_compatible` |
| 角色图、场景图、关键帧 | Banana 2 或兼容图片模型 | `openai_compatible_image` |
| 视频片段 | `doubao-seedance-2-0-mini-260615` | `volcengine_ark_video` |
| 合成成片 | FFmpeg | `ffmpeg_concat` |

配置先保存为候选，再运行“基础预检”。只有人工确认小样本成功后才启用。故事槽位允许同时启用多个模型并按冻结顺序并行；其他 V1 槽位通常只启用一个。系统不会按成本或评分自动切换。

图片和视频真实生产需要供应商可访问的稳定 HTTPS 图片地址。多机生产请设置 `GENERATED_IMAGE_DELIVERY_MODE=s3` 和 `FINAL_VIDEO_DELIVERY_MODE=s3`，并配置 S3/MinIO 凭据及 HTTPS 公共地址。见 [图片结果对象存储说明](图片结果对象存储说明.md)。

## 5. 真实小样本验收顺序

使用一条授权的短视频，只生成：一份分析、三份故事候选、一名角色、一处场景、一份导演分镜、一个关键帧、一个 Seedance 片段和一条测试成片。

每一步检查：任务状态、冻结模型/Prompt、耗时、可用用量/成本字段、输出质量和人工评分。视频要检查供应商任务号、Worker 重启后继续查询、无需重复提交。具体操作见 [真实模型配置操作](LemonFlow_V1_真实模型配置操作.md)。

## 6. 发布前最低检查

```bash
bash infra/scripts/verify_release.sh
```

该脚本检查数据库迁移、后端回归测试、前端生产构建和运维脚本语法。它不配置真实 Key，也不执行收费模型调用。发布后的第一条真实样本仍需要人工复核和账单核对。
